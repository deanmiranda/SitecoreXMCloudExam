Think of an API as a restaurant: the data is the food available, the schema is the menu, your query is your order, and the response is what arrives. Code called a resolver finds the requested data.

Real GraphQL, sample content: this runs inside your browser with a small teaching schema inspired by Sitecore. It is not connected to Sitecore and does not implement every game challenge or Experience Edge feature. Playground experiments do not award challenge points.

Who names what? GraphQL defines rules such as query, fragment and @include. The API schema defines available fields such as item, pageInfo, hasNext and endCursor. You choose operation names, variable names and aliases. Values must match the data you want.

The menu: inspect this playground’s schema
A schema lists the allowed fields, their arguments and the types of answers. String means text; Item means an object whose fields you can choose. A field missing from this menu causes a validation error, even if a similar name exists in the source JSON.
This small schema supports item lookup, named fields, aliases, variables, defaults, fragments on Item, directives and search by _name or _language with EQ/CONTAINS, AND/OR and pagination. Layout, template projections and other Sitecore features stay in the guided challenges.
